# AI 字体生成结果邮件

## 发送时机与内容

- 成功：TTF 完成文件校验、安全审核并存入私有存储后，发送“Your AI font is ready”。
- 最终失败：任务失败且保留积分已通过账本恢复后，发送公开失败原因、实际恢复积分、任务编号和下一步建议。恢复的是站内积分，不是支付退款。
- 排队、生成中、审核重试，以及提交结果不确定的 `needs_review` 状态不发结果邮件。不会自动重提生成请求。
- 收件人取自任务所属 Supabase 账户；邮件只链接到需要登录的 `/my-fonts`，不含提示词、字体附件、带签名的下载链接、上游原始错误或密钥。
- 不补发迁移前已经结束的历史任务。迁移后才结束的在途任务可以正常通知。

## 上线步骤

1. 在现有字体、积分、账单、安全审核和失败原因迁移均已执行的前提下，先执行 `supabase/migrations/202610260001_job_notifications.sql`。不要手工插入历史通知。
2. 部署对应代码。继续使用现有 Worker 的每五分钟 Cron，不需要新建服务。
3. 沿用现有运行时变量 `INBOX_URL`、`INBOX_FROM_EMAIL`、`INBOX_FROM_NAME` 和 Secret `INBOX_SEND_API_KEY`，以及现有 `AI_FONT_APP_URL`、`AI_FONT_CRON_SECRET`、Supabase 服务端配置。不要设置成 `NEXT_PUBLIC_*`，无需为生成邮件另配密钥。
4. 配置不完整时不发送，通知保存在数据库中；启用配置前检查待发队列中是否有测试任务。此操作会允许后续 Cron 发送排队的真实通知。

## 事务、去重与失败处理

`ai_font_job_mail_outbox` 是任务专用通知表，按 `job_id` 唯一。数据库延迟触发器在终态事务结束时读取最终失败原因和已恢复的积分账本，令任务结果、积分结果和通知意图一起提交。发信在事务外执行；发信故障不会撤销字体交付或积分恢复。

现有 Inbox 接口没有可依赖的发送幂等保证。领取任务使用服务端租约和令牌；明确的 429 拒绝采用退避重试，最多八次。超时、连接中断、发送开始后租约过期或接受回执丢失均转入 `needs_review`，不自动重发。先核对邮件服务 Sent 记录及下游结果，再由运维决定如何恢复。永久认证、发件人或配置错误也需要人工处理。

账单和字体通知共用每轮最多一封邮件的预算，按五分钟时间段轮流优先；优先队列为空时处理另一队列。通常有下一轮 Cron 的等待时间，积压、上游限额和故障会进一步延迟，不保证邮件即时或最终送达。收件箱限额仍以邮件服务为准。

`/api/ai-font/reconcile` 保留账单 `mail` 统计，新增字体 `fontMail` 统计，并计入总体 `checked/errors`。关注待发时间、尝试次数和 `needs_review/last_error`，不要在日志中输出邮箱、邮件正文、提示词或原始供应商响应。没有公共发信或重发接口。

本地测试覆盖迁移、终态与积分原子性、历史任务不补发、审核前不可通知、租约去重、429 退避、不确定发送暂停、模板隐私和共享发送预算。测试只用内存 PostgreSQL 与模拟 HTTP，不联系真实生成或邮件服务。
