检查日期：2026-09-05。以下主体保留初次审计结果；用户随后授权的修复及验证状态见下方记录。

## 修复记录

- Unicode 和通用图片工具共享当前会话文字草稿；跨页比较保留原文，混合工具的图像与文字输入同步。Minecraft、ASCII、3D 的专用输入仍各自独立。
- Unicode 复制失败反馈改为可见；主工作区结果保留换行。

## 1. P1：合法长度的长文本仍会被画布裁掉

**位置**：`components/ThreeDFontGeneratorTool.tsx:173`；`components/MinecraftGeneratorTool.tsx:335`；`components/VisualGeneratorTool.tsx:193`；`lib/visual-generator.ts:308`。

- 3D：输入 80 个 W，页面接受输入且标注 Auto-fit，但预览中文字超出左右边缘。缩放到约 42px 就停止，没有确认最终宽度是否已适配。浏览器已复现。
- Minecraft：120 个 W 在 300px 左右的手机画布上不可能以最小 1 倍像素完整容纳。`renderScale` 强制不小于 1，canvas 宽度仍固定为预览宽度，超出部分直接被裁切。函数逻辑确认，浏览器执行了对应输入。
- 通用图片工具：24px 最小字号存在同类边界，字距也不会随字号缩小。Ransom Note 更直接设置 `fitTextToCanvas: false`，长标题连自适应都没有。

**影响**：缺字会进入 PNG/faithful SVG，而不是只影响预览。

**建议**：用实际字形宽度、字距和效果边界统一求布局。位图可以扩大内部画布后按比例显示，保证导出完整；如果坚持最小可读字号，应明确告知超宽并提供换行或扩大画布选项。

## 2. P1：Minecraft 从宽屏变窄时，旧画布宽度撑坏整个编辑区

**位置**：`components/MinecraftGeneratorTool.tsx:304`、`:345`、`:583`。

**浏览器复现**：先以桌面宽度打开，再切到 390px 视口。外层生成器宽 350px，输入框却宽 654px，canvas 宽 652px；输入框、颜色块和预览右边被外层 `overflow-hidden` 裁掉。直接在窄屏刷新后，输入框恢复约 308px。

**原因**：canvas 被写入固定 CSS 像素宽度，Grid 子项缺少允许收缩的约束，ResizeObserver 又读取被内容撑大的容器，形成宽度依赖。

**建议**：编辑列及预览父级设置可收缩约束，分离 canvas 内部分辨率与显示宽度，只根据可见、受约束的容器测量。覆盖横竖屏切换、窗口缩放和浏览器侧栏展开场景。

## 3. P1：部分 Unicode 转换会丢重音和破坏键帽 Emoji

**位置**：`lib/generator.ts:27` 的 `alphaNumericTransform`。

**函数复现**：

| 输入 | 样式 | 实际结果 | 问题 |
|---|---|---|---|
| `e\u0301`（e + 重音） | Bold Script | `𝓮` | 重音丢失 |
| `e\u0301` | Clean Sans | `𝖾` | 重音丢失 |
| `1️⃣` | Clean Sans | `𝟣` | 整个键帽效果消失 |
| `é` | Bold Script | `é` | 与等价分解输入行为不一致 |

虽然已经按 grapheme 分段，但代码只检查每段首个码点，然后返回一个新字符，丢弃其余内容。Bold Serif 的另一套转换逻辑能保留重音，说明两套转换器行为不一致。

**建议**：统一转换入口；只映射普通 Latin 基字符并保留组合附加符，对键帽、ZWJ 等 Emoji 组合保持整体。添加等价 Unicode 表示和 Emoji 回归用例。

## 4. P2：ASCII 静默丢弃第四行和每行第 25 个字符之后的内容

**位置**：`lib/ascii-font.ts:66`；`components/AsciiGeneratorTool.tsx:99`。

**浏览器复现**：输入 `A\nB\nC\nD`，输入框显示四行，结果只有 ABC。输入框只限制总长 72，生成器却另外截取前三行、每行前 24 个字符，页面没有截断反馈。

**建议**：让输入约束和渲染约束一致。优先完整渲染；若限制为三行，应明确显示超限位置及剩余字符，而不是让用户误以为完整内容已导出。

## 5. P2：ASCII 的居中、右对齐会破坏字形

**位置**：`lib/ascii-font.ts:74`；`components/AsciiGeneratorTool.tsx:61`、`:81`。

**函数与代码确认**：F 的七个扫描行宽度分别是 `10, 2, 2, 8, 2, 2, 2`，因为行尾空格被删掉。居中或右对齐又按每个扫描行自己的宽度偏移，因此 F 的竖笔会向中间或右边移动，无法保留原始字形。PNG 与 SVG 的逐行对齐逻辑都受影响。复制/TXT 则完全没有应用 alignment，进一步造成不同输出行为不一致。

**建议**：先把同一段 banner 的所有扫描行补齐为同宽矩形，再对整个矩形对齐。复制、TXT、PNG、SVG 共用排版结果。

## 6. P2：Minecraft 复制代码不会包含面板选中的颜色和格式

**位置**：`components/MinecraftGeneratorTool.tsx:559`。

**代码确认**：选红色、Bold 后预览改变，但 `copyCode()` 始终只写入原始 `gameText`，不会生成颜色和加粗前缀。只有用户手动输入的代码会被保留。浏览器确认控件和成功提示正常响应；本次浏览器剪贴板读取没有返回可用文本，所以复制内容结论以写入函数为依据。

**影响**：用户按“输入—选择颜色/样式—复制代码”的流程操作，粘贴后丢掉刚选的格式。

**建议**：为可表达的基础颜色与格式生成相应代码，并保留内联覆盖规则。渐变、阴影、位置等图像效果无法原样表达时，应在复制区域解释具体限制，并展示待复制代码。

## 7. P2：部分图片预设的文字颜色控件实际上不起作用

**位置**：`components/VisualGeneratorTool.tsx:375`、`:417`。

**代码确认**：当 `currentPreset.gradient` 存在，canvas 和 SVG 都直接使用预设固定渐变，忽略用户调整后的 `controls.textColor`。多色模式也采用固定 palette。页面仍显示可操作的 Text color 控件，容易让用户以为操作失效。

**建议**：把渐变颜色放入可编辑状态，或提供纯色/渐变切换；多色模式提供色板编辑。若某控件当前不适用，应明确禁用并说明。

## 8. P2：切换生成器会丢失刚输入的文字

**位置**：`components/PageTemplate.tsx:225`；`components/GeneratorTool.tsx:379`。

**浏览器复现**：首页输入 `Alice\nBob`，点击目录里的 Small，输入框变回 `Small Text Generator`。组件按 slug 重建，输入状态只保存在当前实例。已有目录滚动位置保存，却没有保存用户正在比较的文本。

**建议**：通过共享客户端状态或 sessionStorage 保留当前文本，让同一句话可以跨生成器比较；首次访问才使用示例。返回上一工具也应恢复草稿。

## 9. P2：复制失败反馈不可见，ASCII 成功反馈也不可见

**位置**：`components/GeneratorTool.tsx:486`、`:828`、`:1231`；`components/AsciiGeneratorTool.tsx:33`、`:132`。

**代码确认**：Unicode 复制失败信息只放在 `sr-only` live region，普通视觉用户看不到“浏览器阻止复制”的解释。ASCII 复制没有 try/catch，也没有按钮成功状态，成功消息同样只提供给读屏。PNG 状态在 `toBlob` 成功之前就宣布 downloaded。

**建议**：提供可见成功/失败反馈，失败时保留可选中文本并提供手动复制提示；只在拿到有效 Blob 并触发下载后报告成功。

## 10. P2：混合生成器的图片和可复制文字使用两份独立输入

**位置**：`components/PageTemplate.tsx:207`。

**浏览器与代码确认**：Ransom Note 图片区默认 `SECRET MESSAGE`，下方复制区默认 `Ransom Note Font Generator`，两个独立组件各自维护输入。编辑图片区不会自动更新下方文本区。Brat、Fire、Glitter 同属此结构。

**影响**：用户以为下方是当前设计的文字替代版，实际却可能复制到完全不同的内容；手机上还需要滚过一整套控制区才能发现第二份输入。

**建议**：提升共享输入状态，切换图片/文字输出时保留同一内容；若确实需要独立内容，应提供明确的“使用上方文本”操作。

## 后续体验改进（不作为同级功能缺陷）

- 通用图片工具在手机上预览位于控件上方，调整下方参数时不容易同时看到变化。可以折叠高级控制，或使用有尺寸上限的固定预览。
- Unicode 结果段落未保留输入的换行和连续空格；复制出来却仍包含它们。应让预览保留空白，减少所见与所复制内容的差异。
- 主输入框预填的是页面名称，用户第一次输入前需要清除；可把示例展示与实际输入分开，或者增加明确的示例加载按钮。
- Editable SVG 简化逐字特效、可能字体回退；faithful SVG 是嵌入 PNG。项目已经解释这些限制，不能把所有差异当作 bug，但手机上的导出按钮附近也应有简短说明，避免误以为 faithful SVG 是可无限放大的真正矢量字形。
- ASCII 对不支持字符直接替换为问号，标点支持也只有少量字符。可在输入旁实时列出不支持的字符。

## 建议修复顺序

1. 修复文字完整性：长文本裁切、Unicode 组合字符丢失、ASCII 静默截断。
2. 修复结果正确性：ASCII 对齐、Minecraft 代码序列化、无效颜色控件。
3. 修复使用流程：Minecraft 窄屏切换、跨页保留文本、混合输入同步、复制与下载反馈。
4. 用针对性回归用例覆盖这些已复现边界，再做真实移动设备与导出文件验证。
